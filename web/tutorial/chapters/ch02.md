# 第2章 项目管理：隔离与共享知识库

KS 采用「**多项目、知识库隔离**」的设计：每个项目拥有独立的私有知识库，同时支持一个跨项目共享的 `_shared` 库。本章讲解如何创建项目、切换项目，以及把私有知识晋升到共享库。

## 为什么需要项目隔离

不同产品线、不同团队的文档与知识不应互相污染。KS 把每个项目的知识存放在独立目录：

```
brains/
  default/        # 默认项目
  tg-yja078186/   # 示例项目「AI计算集群仿真系统」
  _shared/        # 跨项目共享库
```

导入、抽取、问答、图谱等全部基于「当前项目」的范围。这样你可以在同一套系统里并行服务多个项目，互不干扰。

## 案例 1：新建一个项目

1. 在顶栏点击 **「新建项目」** 按钮（图标为 `+`）。
2. 在弹出的对话框中填写：
   - **项目名称**：如「自动驾驶仿真平台」；
   - **描述**（可选）；
   - 系统会生成一个项目 ID 与对应的私有知识库目录。
3. 点击 **创建**，项目即出现在项目下拉中，并自动切换为当前项目。

## 案例 2：在多个项目间切换

切换方式有两种：

- **顶栏下拉**（推荐）：点击顶栏项目名，选择目标项目，页面整体刷新。
- 切回任意已有项目后，知识库、草稿、冲突、图谱等都会只显示该项目的数据。

> 提示：切换项目后，若某模块列表为空，通常是因为该项目尚未导入数据，属正常现象。

## 案例 3：把私有知识晋升到共享库

当某条知识（例如一条通用质量规则）需要被多个项目复用时，可把它**晋升（promote）**到 `_shared` 共享库：

1. 进入 **知识库** 页，打开一条知识详情。
2. 点击详情中的 **「晋升到共享库」** 按钮。
3. 确认后，该知识会被复制到 `_shared`，所有项目都可读到它；原私有条目保留不动。

> 晋升是「复制」语义：共享库中的副本与原私有条目相互独立，后续各自演进不会互相覆盖。

## 私有库 vs 共享库对照

| 维度 | 私有库 `brains/<pid>` | 共享库 `_shared` |
|------|----------------------|------------------|
| 可见范围 | 仅所属项目 | 所有项目 |
| 写入来源 | 该项目导入/编辑 | 任意项目晋升 |
| 典型内容 | 项目专属 PRD、缺陷经验 | 通用质量规则、通用规范 |

## 小结

- 每个项目知识隔离，互不干扰；
- 新建/切换项目都在顶栏完成；
- 通用知识通过「晋升」进入 `_shared` 实现跨项目复用。
