# 第6章 冲突处理：当知识发生碰撞

当同一知识被多处修改、或导入与已有条目重叠时，KS 会标记为**冲突**，交由人工裁决。本章讲解冲突的来源与解决方式。

## 冲突是怎么产生的

典型场景：

- 同一份 PRD 被不同人分别编辑并提交；
- 新导入的内容与知识库中已有条目高度重叠；
- 共享库与私有库存在同名知识被同时修改。

系统不会擅自覆盖，而是把冲突项放进 **冲突处理** 页，等待人工决议。

## 冲突处理页

进入 **冲突处理** 页，列出当前项目的所有冲突，每条显示：冲突双方内容、来源、冲突类型。

![冲突处理](/tutorial/assets/conflicts.png)

> 图6-1 冲突处理页：逐条列出冲突，并提供解决方式。

## 四种解决方式

| 方式 | 含义 | 结果 |
|------|------|------|
| 合并（merge） | 双方内容合并 | 合并结果入库，原冲突消解 |
| 覆盖（overwrite） | 用新内容覆盖旧内容 | 新内容入库 |
| 保留双方（keep_both） | 双方都保留 | 新草稿入库（旧条目本就在库） |
| 丢弃（discard） | 放弃本次变更 | 冲突消解，知识库不变 |

## 案例：解决一条冲突

1. 打开 **冲突处理** 页，找到一条冲突；
2. 对比「现有内容」与「待入库内容」；
3. 选择 **合并**，系统把合并结果写回知识库（经质量门控）；
4. 该冲突从列表中消失，对应草稿状态流转为已合入（不再悬挂）。

> 提示：冲突解决是**闭环**操作——处理后会同步更新草稿状态并回写知识库，避免草稿长期悬挂在 `conflict` 状态。

## 小结

- 冲突由并发修改/重叠导入引起，系统不擅自覆盖；
- 提供 合并 / 覆盖 / 保留双方 / 丢弃 四种裁决；
- 处理后自动闭环，知识库与草稿状态保持一致。
