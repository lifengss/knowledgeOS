# 第3章 导入源数据：让 PRD/代码/缺陷沉淀为知识

KS 的核心价值，是把散落在文档与仓库里的**源数据**自动转化为**结构化知识**。本章讲解如何导入，以及导入后会发生什么。

## 导入入口

点击顶栏的 **「导入」** 按钮，打开导入对话框。

![导入弹窗](/tutorial/assets/import.png)

> 图3-1 导入对话框：选择源数据类型、目标项目，并提交文件。

## 导入对话框字段

| 字段 | 说明 |
|------|------|
| 源数据类型 | PRD / 代码 / 缺陷 / 其它，决定抽取策略 |
| 目标项目 | 默认跟随当前项目，可覆盖为其它项目 |
| 文件 | 支持多份文件（如一份 PRD + 若干代码） |

## 导入后发生了什么

提交后，系统会：

1. 读取源文件内容（自动识别 UTF-8 / GBK 编码）；
2. 按类型抽取知识要点；
3. 生成若干**草稿**，经质量门控后落库为对应分类的知识条目：
   - PRD → 项目 Wiki 文档 + 可能的质量规则；
   - 代码 → API/接口知识、业务流程；
   - 缺陷 → 缺陷经验、质量规则、测试用例。

![导入后的知识库](/tutorial/assets/brain.png)

> 图3-2 导入完成后，在「知识库」页即可看到自动生成的结构化知识条目。

## 案例：上传一份 PRD 自动沉淀知识

1. 顶栏点击 **导入**。
2. 源数据类型选 **PRD**，目标项目保持当前项目。
3. 选择本地 PRD 文件（如 `架构设计与技术方案.md`）。
4. 点击 **提交**，等待右下角进度提示完成。
5. 进入 **知识库** / **项目 Wiki**，即可看到新生成的条目与文档。

> 提示：入库需通过**质量门控**（总分≥60）。源内容应包含 Markdown 标题、列表、代码块等规范结构，否则可能被拒，此时草稿会停留在「待处理」状态，可在草稿箱重新提交。

## 小结

- 导入是把「原始资料」变为「知识资产」的入口；
- 不同类型走不同抽取策略，最终落到对应分类；
- 入库受质量门控约束，规范的结构化内容更容易通过。
