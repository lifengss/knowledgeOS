# 第11章 质量监控与审计：掌握系统健康度

KS 不仅沉淀知识，也提供**质量监控**与**审计日志**，让你掌握知识库的健康度与每一次变更的来龙去脉。

## 质量监控（dashboardStats）

进入 **质量监控** 页，仪表盘展示：

- **类型覆盖**：按已发布 Brain 页面的分类统计数量（质量规则 / 缺陷经验 / 缺陷规则 / 项目 Wiki / 测试用例 / 自动化脚本）；
- **趋势**：知识条目随时间的变化曲线；
- 其它健康度指标卡片。

![质量监控](/tutorial/assets/quality.png)

> 图11-1 质量监控仪表盘：分类覆盖与趋势一目了然。

> 提示：类型覆盖基于**已发布**的 Brain 页面统计，与知识库浏览计数口径一致，避免因草稿类型造成重复计数。

## 审计日志（audit）

进入 **审计日志** 页，可按动作、操作人、目标筛选，浏览每一次知识变更的完整记录。每条记录包含：

- `action`：操作类型（如导入、提交、编辑提案、晋升）；
- `operator`：操作人；
- `target`：作用对象；
- `project`：所属项目；
- `created_at`：带时区的时间戳。

![审计日志](/tutorial/assets/audit.png)

> 图11-2 审计日志：可追溯每一次知识变更的 action / operator / target / 时间。

## 案例：追踪一条知识是怎么来的

1. 在知识库找到一条质量规则，记下其标题；
2. 进入 **审计日志**，筛选 `target` 含该标题（或按动作 `create_page` / `batch_create_page`）；
3. 查看记录，确认是谁、在哪个项目、何时通过什么动作创建/修改了它。

> 提示：审计接口只认 `pageSize`（默认 20）分页参数，列表的「总条数」随真实总数返回，便于翻页核查。

## 小结

- 质量监控看「知识覆盖是否均衡、是否在增长」；
- 审计日志看「每一次变更由谁在何时做了什么」；
- 两者结合，让知识库的演进可观测、可问责。
